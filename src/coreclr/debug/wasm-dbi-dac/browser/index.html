CoreCLR wasm DBI/DAC browser smokes

Pick a smoke to run. Each page instantiates the wasm runtime + sidecar and reports PASS/FAIL inline.

  • hello-async-break The cooperative IDE-driven async-break demo. Clicks the link with ?wait-for-external-dbi=1 so the page waits for the external CDP orchestrator (started automatically by ./serve-smokes.sh) to drive the 8-step demo. Without that gate (e.g. opening this URL directly), the page runs the bare busy loop with no async-break.
  • hello-breakpoint Sets a managed breakpoint, validates the structured DBI IPC event drained via DAC ReadVirtual, real InterpMethod locals + values, and PDB source-location mapping.
  • hello-cdp-pause Runs a managed busy loop. Open DevTools (F12) and press F8 to pause mid-loop via CDP Debugger.pause; press F8 again to resume. No JSPI/Asyncify required.
  • hello-module-load Observes structured module-load DBI events (WasmDbgIpcEventModuleLoad) drained via the sidecar DAC as managed assemblies load.
  • hello-exception Throws and catches a managed exception; validates the structured first-chance exception DBI event (WasmDbgIpcEventException) drained via the sidecar DAC.
See src/coreclr/debug/wasm-dbi-dac/browser/README.md for build + Playwright usage. window.__smokeResult on each smoke page exposes the structured result for automated drivers.
