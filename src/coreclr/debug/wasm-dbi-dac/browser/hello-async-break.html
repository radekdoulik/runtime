    This page demonstrates the cooperative IDE async-break path. The page
    itself simulates the mscordbi role — it loads the runtime, starts a busy
    loop, then sends a cooperative async_break_request. The runtime
    checks the request flag at the next sequence point, halts cleanly, populates
    a locals schema record, emits a structured DBI event, and yields control
    via V8's debugger; statement. No external CDP client is
    required to drain the event — but if one is attached, the runtime
    really does freeze until the IDE resumes.
  

  

    Demo flow with a CDP client attached (Chrome DevTools open, or a Playwright
    test that called Debugger.enable):
    
    
      
  1. page sends cooperative async_break_request ~800ms into the busy loop
    2. 
      
  2. runtime halts at next IL sequence point and populates g_wasmDebugLastIpcAsyncBreak + g_wasmDebugLastLocalsRecord
    3. 
      
  3. page-side handler drains the structured event and reads the locals schema via DAC enumerate_locals (real DBI/DAC round-trip)
    4. 
      
  4. page renders the "Simulating IDE debug pause" panel with the locals it just read
    5. 
      
  5. handler returns → runtime's libCorerun.js wrapper executes debugger; → V8 freezes the wasm caller
    6. 
      
  6. IDE inspects state, then issues Debugger.resume after a 5-second hold (simulating a human at the IDE)
    7. 
      
  7. wrapper returns to wasm → runtime clears the async-break flag → loop runs to completion
    8. 
    

    With no CDP client attached, debugger; is a no-op and the loop
    appears to run uninterrupted, but the structured event AND the locals were
    still drained and rendered to the panel above.
